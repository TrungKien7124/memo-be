TAI LIEU THIET KE BACKEND - MEMO (BAN CAP NHAT)

1) MUC TIEU
- Modular monolith, co san CRUD, de tap trung vao nghiep vu chinh ve sau.
- San sang cho realtime (Channels), async jobs (Celery), cache (Redis).

2) CONG NGHE SU DUNG
- Django 4.2 + Django REST Framework
- PostgreSQL (default), SQLite (dev fallback neu khong cau hinh Postgres)
- Redis (cache, Celery broker/result, Channels layer)
- Celery (async jobs)
- Django Channels (websocket)

3) KIEN TRUC TONG THE
- 3 Django app:
  - app_server (IAM, CMS, LMS, NFS, SOC, GMS, NTS, ADM)
  - srs (SRS + RSE)
  - ai (ACS + SPS)
- Core layer dung chung nam trong app_server (base controller/serializer/normalizer/validator/pagination/exceptions).
- Cac app con ke thua core tu app_server.

4) CAU TRUC THU MUC
- memo_backend/
  - settings.py: cau hinh Django, DRF, CORS, Celery, Channels, auth model
  - urls.py: router goc + include urls tung app
  - asgi.py, wsgi.py: entrypoints
  - routing.py: websocket routes placeholder
  - celery.py: cau hinh celery
- apps/app_server/
  - controllers/{base,implemented,extended}
  - models/{base,implemented,extended}
  - serializers/{base,implemented,extended}
  - normalizers/{base,implemented,extended}
  - validators/{base,implemented,extended}
  - routes/{base,implemented,extended}
  - pagination/base
  - exceptions/base
  - management/commands/seed_demo.py
- apps/srs/
  - controllers/{base,implemented,extended}
  - models/{base,implemented,extended}
  - serializers/{base,implemented,extended}
  - normalizers/{base,implemented,extended}
  - routes/{base,implemented,extended}
- apps/ai/
  - controllers/{base,implemented,extended}
  - models/{base,implemented,extended}
  - routes/{base,implemented,extended}

5) QUY UOC DAT TEN FILE
- Model: <domain>_<entity>_model.py (vd: iam_user_model.py, srs_card_srs_state_model.py)
- Controller: <domain>_<entity>_controller.py
- Serializer: <domain>_<entity>_serializer.py
- Normalizer: <domain>_<entity>_normalizer.py
- Route: <domain>_route.py
- Base: app_server_base_*.py

6) AUTH VA USER
- Su dung Django auth voi custom user:
  - AUTH_USER_MODEL = app_server.User
  - User ke thua AbstractUser, them field role.
- Password luu theo set_password.

7) ERROR RESPONSE FORMAT
- Tat ca loi API duoc chuan hoa boi `apps/app_server/exceptions/base/app_server_base_exceptions.py`.
- Format:
  {
    "error": {
      "type": "validation_error | auth_error | not_found | api_error",
      "message": "...",
      "details": { ... }
    },
    "data": { ... }  // payload FE gui len
  }

8) PAGINATION
- Mac dinh dung `apps/app_server/pagination/base/app_server_base_pagination.py`.
- Response:
  {
    "data": [ ... ],
    "meta": {
      "count": 123,
      "page": 1,
      "page_size": 20,
      "next": "...",
      "previous": "..."
    }
  }

9) CRUD CO BAN
- CRUD duoc cung cap boi CoreModelViewSet + CoreModelSerializer.
- Serializer khai bao:
  - field_list
  - ignore_fields
  - validation_rules
- Normalizer de chuan hoa input theo field.

10) HEALTH CHECK
- Global: GET /health/
- Moi domain: GET /api/<domain>/health/

11) SEED DATA
- Lenh: python manage.py seed_demo
- Tao user demo, profile, course/module/lesson, progress, flashcard, srs state, review log.

12) GHI CHU VE SERVICE/USECASE (DE MO RONG)
- Service: logic nghiep vu thuan (tinh stage SRS, tinh XP).
- Usecase: dieu phoi nhieu service/model trong 1 flow (ket thuc session, update log + SRS).
- Controller chi xu ly request/response.

13) CAC MODEL HIEN CO
- app_server:
  - IAM: User, UserProfile
  - CMS: Course, Module, Lesson
  - LMS: LessonProgress
  - NFS: Folder, Flashcard
  - SOC/GMS/NTS/ADM: scaffold
- srs:
  - SRS: CardSRSState
  - RSE: ReviewSession, CardReviewLog
- ai:
  - ACS/SPS: scaffold

14) API LIST (CRUD + HEALTH)
- app_server:
  - /api/iam/health/ + /api/iam/users/ + /api/iam/profiles/
  - /api/cms/health/ + /api/cms/courses/ + /api/cms/modules/ + /api/cms/lessons/
  - /api/lms/health/ + /api/lms/lesson-progress/
  - /api/nfs/health/ + /api/nfs/folders/ + /api/nfs/flashcards/
  - /api/soc/health/
  - /api/gms/health/
  - /api/nts/health/
  - /api/adm/health/
- srs:
  - /api/srs/health/ + /api/srs/card-srs/
  - /api/rse/health/ + /api/rse/review-sessions/ + /api/rse/card-review-logs/
- ai:
  - /api/acs/health/
  - /api/sps/health/

15) SEQUENCE FLOW - SRS (ON TAP FLASHCARD)
- POST /api/rse/review-sessions/ -> tao ReviewSession
- GET /api/srs/card-srs/?due_date__lte=today -> lay card due (logic se bo sung o service/usecase)
- POST /api/rse/card-review-logs/ (choice easy/hard)
- Update CardSRSState (stage, interval_days, due_date)
- PATCH /api/rse/review-sessions/{id}/ set ended_at

16) SEQUENCE FLOW - SPEAKING (SPS)
- POST /api/sps/... (sau nay)
- Audio -> STT -> text
- AI sinh phan hoi (RAG/LLM)
- Luu log va cong XP (sau nay)
